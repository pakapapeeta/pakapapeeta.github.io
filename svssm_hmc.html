1 · Executive Summary

Purpose. A self-contained command-line experiment that performs Bayesian parameter recovery for a stochastic-volatility model. It (1) simulates a time series with known true parameters, (2) runs Hamiltonian Monte Carlo (HMC) to draw from the posterior over those parameters given the data, and (3) checks whether the posterior actually recovers the truth, emitting numeric diagnostics and plots.

Primary responsibility. Glue code around a third-party differentiable likelihood. The file owns: data generation, the unconstrained reparameterisation + prior (the "target log-posterior"), two HMC samplers (vanilla and a hand-rolled Stan-style windowed adaptive sampler), convergence diagnostics (R-hat, ESS), and reporting (txt/json/npz + matplotlib figures).

The statistical model docstring is the canonical SV model:

h_t = mu + phi*(h_{t-1} - mu) + sigma_eta * eta_t      (latent log-volatility, AR(1))
y_t = exp(h_t / 2) * eps_t                              (observation)
eta_t, eps_t ~ N(0,1)

Three scalar parameters are inferred: level mu, persistence phi ∈ (-1,1), and volatility-of-volatility sigma_eta > 0.

Main components (top to bottom): data generation (gen_svssm) → target construction (make_target_log_prob, unconstrain, constrain) → samplers (run_chain and its windowed engine run_chain_windowed_proper, built on the helpers _build_preconditioned_kernel, _trace_preconditioned, _run_window) → diagnostics (split_rhat, ess_bulk, summarise_posterior) → output (_write_reports_and_plots, _aggregate_from_chains) → the main driver with three run modes.

Execution overview. main() parses CLI args and branches into one of three modes: aggregate (load saved chains, only diagnose), single-chain (run exactly one chain, save it — for parallel launchers), or sequential (run all chains in-process). Normal flow: generate data → build the filter object → build the target → run N chains from dispersed starts → stack samples to shape (chains, draws, 3) → compute diagnostics → write reports.

Known, deliberate bias docstring: the Harvey–Ruiz–Shephard Gaussian quasi-likelihood biases sigma_eta upward ~30–50%, so a posterior mean of sigma_eta above truth is the expected, documented behaviour — not a bug. mu and phi should land near truth.

4 · Execution Flow

Entry point: if __name__ == "__main__": raise SystemExit(main()). Using raise SystemExit(main()) turns main()'s integer return into the process exit code (0 = success) — the conventional CLI pattern.

  1. Parse args → make out_dir and out_dir/chains.
  2. Print config banner (TF/TFP versions, truth, kernel label, mode).
  3. Mode branch #1 — aggregate: if --aggregate, call _aggregate_from_chains, summarise, write reports, return (no sampling at all).
  4. Generate data: y_obs = gen_svssm(...).
  5. Build filter: instantiate the likelihood object ll.
  6. Dispersed inits: truth_raw via unconstrain, then add Gaussian jitter (dispersion) per chain.
  7. Build target: target_log_prob_fn = make_target_log_prob(...).
  8. Mode branch #2 — single chain: if --chain_id set, run that one chain, save chains/chain_{id}.npz, return.
  9. Mode branch #3 — sequential: loop over chains, each calling run_chain; collect results.
  10. Stack to (chains, draws, 3); constrain to natural space.
  11. Diagnose via summarise_posterior.
  12. Report via _write_reports_and_plots; return 0.

gen_svssm(T, mu, phi, sigma_eta, seed) → tf.Tensor

def gen_svssm(T, mu, phi, sigma_eta, seed):
    tf.random.set_seed(seed)
    sigma_eta_t = tf.constant(sigma_eta, tf.float32)
    h = tf.constant(float(mu), tf.float32)        # h_0 initialised AT mu
    ys = []
    for _ in range(T):
        h = mu + phi * (h - mu) + sigma_eta_t * tf.random.normal([])
        ys.append(tf.exp(h / 2.0) * tf.random.normal([]))
    return tf.stack(ys)

Signature

Tint — number of time steps to simulate.
mufloat — long-run mean of log-volatility.
phifloat — AR(1) persistence, expected in (-1,1).
sigma_etafloat — std of the volatility innovation (note: NOT the variance).
seedint — global TF RNG seed for reproducibility.

Return value

A 1-D tf.float32 tensor of shape (T,) — the observed series y_t. code

Step-by-step

  • tf.random.set_seed(seed) — fix the global RNG so the series is reproducible.
  • h = mu — initialise the latent state at the mean (not drawn from the stationary distribution). inference: this introduces a short burn-in transient; for the AR(1) here it's mild because the chain starts at its mean.
  • The loop applies the AR(1) recursion h ← mu + phi*(h−mu) + sigma_eta*η and emits y = exp(h/2)*ε. Each iteration draws two independent standard normals (η then ε).
  • tf.stack(ys) — concatenate the T scalars into one tensor.

Variable tracking

h evolves in-place across iterations (the only carried state). sigma_eta_t is a constant; mu/phi are Python floats promoted into the graph each step.

Complexity

Time O(T) with a Python-level loop (eager, one op-set per step). Memory O(T) for the list + stacked tensor.

Edge cases / bugs

  • |phi| ≥ 1: non-stationary — h can drift unboundedly and exp(h/2) overflow to inf. Not guarded.
  • sigma_eta < 0: accepted silently; flips the innovation sign (harmless for a symmetric normal, but conceptually invalid).
  • Python loop in eager mode is slow for large T; fine for the default T=50/100. A tf.scan would vectorise it.
  • Two RNG draws per step share the same seeded stream — correct, but means changing T changes the entire downstream draw sequence.

make_target_log_prob(...) → callable

Full walkthrough (the statistical core of the file)

This factory captures the likelihood object, the data, priors and a common-random-number (CRN) seed, then returns a closure target_log_prob(theta_raw) that HMC differentiates and samples.

Parameterisation

theta_raw = [mu, phi_raw, log_sigma_eta_sq] lives in unconstrained ℝ³. Inside the closure:

phi          = tanh(phi_raw)            # maps ℝ → (-1, 1): enforces stationarity
sigma_eta_sq = exp(log_sigma_eta_sq)    # maps ℝ → (0, ∞): enforces positivity

Why unconstrained? HMC simulates Hamiltonian dynamics in ℝ^d; hard bounds would require reflecting/rejecting trajectories. Reparameterising to ℝ removes the boundaries so leapfrog runs freely. inference (standard MCMC practice)

Priors

Three independent Gaussians, built once outside the closure (so they aren't re-instantiated every gradient eval):

prior_muN(loc, scale²) on mu directly.
prior_phi_rawN on phi_raw (the pre-tanh value).
prior_log_sigma_eta_sqN on log_sigma_eta_sq.
Subtle point. Priors are placed on the unconstrained coordinates, not on phi/sigma_eta_sq. The code does not add a Jacobian (log-derivative) term for the tanh/exp transforms. That is a deliberate modelling choice: the prior is defined in unconstrained space, so no change-of-variables correction is needed. inference If you instead wanted a specific prior on phi itself, you would need the log|d phi/d phi_raw| term. This is a classic interview trap (see §14).

The closure body

def target_log_prob(theta_raw):
    tf.random.set_seed(int(crn_seed))                 # (1) CRN fix
    mu = theta_raw[0]; phi_raw = theta_raw[1]; log_sigma_eta_sq = theta_raw[2]
    phi = tf.tanh(phi_raw); sigma_eta_sq = tf.exp(log_sigma_eta_sq)
    log_prior = prior_mu.log_prob(mu) + prior_phi_raw.log_prob(phi_raw) \
                + prior_log_sigma_eta_sq.log_prob(log_sigma_eta_sq)
    if no_likelihood:
        return log_prior                              # (2) prior-only baseline
    log_lik = ll(mu, phi, sigma_eta_sq, y_obs)
    log_lik = tf.cast(tf.math.real(log_lik), tf.float32)   # (3) drop imag part
    log_lik = tf.where(tf.math.is_finite(log_lik), log_lik, -inf)  # (4) -inf guard
    return log_prior + log_lik
  1. CRN seed fix comment: resetting the global seed every evaluation makes the particle-filter estimate a deterministic function of theta within a chain. HMC's leapfrog assumes a smooth, fixed potential energy surface; if the likelihood's Monte-Carlo noise changed every call, energy wouldn't be conserved and acceptance would collapse. Fixing the seed restores that.
  2. no_likelihood: a prior-only mode used to measure where the chain settles under the prior alone — a sanity check that the data actually moves the posterior.
  3. tf.math.real: the likelihood may return a complex dtype inference (e.g. from a spectral/eigen step inside the filter); only the real part is the log-likelihood.
  4. -inf not -1e6 comment: the most important numerical detail. A finite sentinel like -1e6 makes the Metropolis ratio between two equally bad states ≈1 (always accept), which tricks dual-averaging into thinking huge step sizes are safe. -inf forces a clean MH rejection.

Complexity

Per call: O(prior) trivial + one full filter pass (the dominant cost, hidden in ll). HMC calls this ~num_leapfrog times per step.

Edge cases

  • If ll returns NaN/Inf for extreme params, (4) catches it → proposal rejected.
  • theta_raw must be a length-3 tensor; indexing [0..2] assumes that shape.
  • Resetting the global seed inside the target affects any other TF RNG in the process — fine here because nothing else draws during a gradient eval, but a footgun if reused elsewhere.

unconstrain(mu, phi, sigma_eta_sq) & constrain(theta_raw)

unconstrain: [mu, arctanh(clip(phi, ±0.9999)), log(max(sigma_eta_sq, 1e-8))]
constrain:   [mu, tanh(th[...,1]), exp(th[...,2])]   # vectorised over leading dims
  • These are the host-side (NumPy) inverses of the in-graph transforms. unconstrain maps a single natural triple → theta_raw for initial states; constrain maps sample arrays back to natural space using th[..., k] so it works on shape (chains, draws, 3) in one call.
  • Defensive clipping: arctanh(±1)=±∞, so phi is clipped to ±0.9999; sigma_eta_sq is floored at 1e-8 before log to avoid -inf.
  • Naming gotcha: unconstrain takes sigma_eta_sq (the variance), and callers pass args.sigma_eta ** 2. Mixing up sigma vs sigma² here is a common bug — note main passes the square correctly.

Complexity O(1) / O(n) elementwise. Edge case: constrain assumes the last axis has length ≥3.

_build_preconditioned_kernel(...)

Kernel construction & the DualAveraging getter/setter plumbing

Builds a PreconditionedHamiltonianMonteCarlo inner kernel; if num_adaptation_steps is None returns it bare (sampling phase), else wraps it in DualAveragingStepSizeAdaptation.

inner = tfp.experimental.mcmc.PreconditionedHamiltonianMonteCarlo(
    target_log_prob_fn, step_size, num_leapfrog_steps, momentum_distribution=momentum_dist)
if num_adaptation_steps is None: return inner
return tfm.DualAveragingStepSizeAdaptation(
    inner_kernel=inner, num_adaptation_steps=..., target_accept_prob=...,
    step_size_setter_fn = lambda kr, ss: kr._replace(accepted_results=kr.accepted_results._replace(step_size=ss)),
    step_size_getter_fn = lambda kr: kr.accepted_results.step_size,
    log_accept_prob_getter_fn = lambda kr: kr.log_accept_ratio)

Why the custom getter/setter lambdas? DualAveraging needs to read and write the step size buried inside the kernel-results namedtuple tree. The default accessors assume a particular layering; because the inner kernel is Preconditioned HMC (an extra wrapper), the code provides explicit functions that walk the documented structure:

DualAverage.results
 └ inner_results = MetropolisHastingsKernelResults
    ├ accepted_results = UncalibratedPreconditionedHMC.results  → .step_size
    └ log_accept_ratio

The momentum distribution = the mass matrix. Preconditioning is supplied via momentum_distribution; this is how the windowed sampler injects an adapted mass matrix (see below and §7).

Complexity O(1) construction. Edge case: if the kernel-results structure changes across TFP versions, the lambdas break — a version-coupling risk.

_trace_preconditioned(_, kr)

if hasattr(kr, "new_step_size"):     # adapted: DualAveraging on top
    step = kr.new_step_size; mh = kr.inner_results
else:                                # bare PreconditionedHMC (sampling phase)
    mh = kr; step = mh.accepted_results.step_size
return mh.is_accepted, cast(mh.accepted_results.target_log_prob), cast(step)

A unified trace_fn that returns (accepted, log_prob, step_size) for both kernel layerings. The hasattr(kr, "new_step_size") probe distinguishes the adapted wrapper (which exposes new_step_size) from the bare kernel. This duck-typing lets _run_window use one trace function in both warmup and sampling phases. O(1). Edge case: relies on the attribute name new_step_size staying stable in TFP.

_run_window(...) → (final_state, samples, acc, lp, step_arr, final_step)

One block of HMC; the smoothed-step-size logic

Runs num_steps steps of (optionally adapted) PreconditionedHMC via tfm.sample_chain, with num_burnin_steps=0 (warmup is managed externally by the windowing logic, not by sample_chain).

Adapted branch (adapt_step_size=True): passes return_final_kernel_results=True and then reads the smoothed step size:

arr = np.asarray(tf.exp(final_kr.log_averaging_step).numpy())
smoothed = float(arr.flatten()[0]) if arr.size > 0 else 0.0
final_step = smoothed if smoothed > 0 else float(step_arr[-1].numpy().flatten()[-1])

Why the smoothed estimate? comment Nesterov dual-averaging maintains a running average log_averaging_step (what Stan reports). It is far less noisy than the last raw new_step_size, especially in short windows where adaptation hasn't fully converged. The try/except falls back to the last traced step if the attribute is missing/zero.

Non-adapted branch: step size is frozen, so it just returns the input step_size without inspecting the trace.

Variable tracking: final_state = samples[-1] threads the chain forward to the next window. Complexity: O(num_steps × leapfrog × cost(ll)). Edge cases: the nested .numpy().flatten() indexing guards against scalar-vs-array shape ambiguity in the traced step array.

run_chain_windowed_proper(...)

Stan-style windowed adaptive HMC — the most intricate function

Implements warmup as a sequence of expanding windows that each (a) adapt the step size and (b) re-estimate the mass matrix from that window's own samples, then a frozen sampling phase. This is a hand-rolled version of Stan/TFP's DiagonalMassMatrixAdaptation, written to avoid a specific instability.

Window budget

phase1_n     = max(B*0.10, 5)          # init window: identity mass, step-size only
phase2_total = max(B - phase1_n, 18)
w1 = max(phase2_total//8, 4)
w2 = max(phase2_total//4, 6)
w3 = max(phase2_total - w1 - w2, 8)    # "super-window": last mass est + term role

Key design comment: there is no separate terminal phase. The last expanding window (w3) does NOT update the mass matrix at its end; instead it doubles as the "term" window where the step size converges against the final mass matrix that sampling will use. Earlier versions had a short separate term phase that failed: a fresh mass matrix at term start forced the step to re-equilibrate with too few steps left.

Mass-matrix convention (the crux)

Mass matrix M := posterior_cov⁻¹. The momentum_distribution covariance is set to M = precision (inverse posterior covariance), not the covariance itself. The leapfrog position update q += eps·M⁻¹·p then scales by the posterior covariance, so high-variance directions take proportionally larger steps. The comment explicitly flags a prior bug ("v4 passed sample variance directly as momentum scale² — wrong direction") that was masked only because all three SVSSM params happen to have similar posterior scale. comment

Two mass modes

  • dense (default): MultivariateNormalTriL momentum with full inverse-covariance — captures off-diagonal correlation like the (phi, sigma_eta²) ridge (~−0.79 at T=100).
  • diagonal: Independent(Normal) per-dim only — cheaper, cannot fix correlations.

Precision estimators (with clipping)

diag:  var = clip(reduce_variance(win), 0.1, 10);  precision = 1/var
dense: cov = covariance(win) + 1e-4·I; symmetrise; eigh → clip eigenvalues to [0.1,10];
       rebuild cov; precision = inv(cov_clip); symmetrise

Why clip? comment Identity mass ≡ var 1, so [0.1, 10] allows a 10× rescale either way. It prevents the "briefly-stuck-chain" pathology where a window's variance → 0 makes precision (and trajectory length) explode. The dense version clips eigenvalues — bounding per-direction scale while preserving the eigenvectors (the correlation structure).

Flow of the function

  1. Init momentum = identity mass (no adaptation yet).
  2. Init window: _run_window(adapt=True); clip eps to [1e-4, 0.3].
  3. For each expanding window: run with current mass + step-size adapt; clip eps; if not the last window, estimate precision from the window's post-burn samples (skip = 25%) and rebuild the momentum distribution.
  4. Sampling: no adaptation, frozen step + frozen mass, chunked into progress_every blocks for heartbeat logging + ETA.
  5. Concatenate chunks; synthesize a constant step_arr (since step is frozen); return NumPy arrays.
Why reset the step-size adapter each window? comment The monolithic DualAverage[DiagonalMass[PHMC]] stack updates two adapters independently every step; they can co-amplify and drive the step size to inf on bad geometry. Resetting DA at each window boundary breaks that feedback loop — the central reason this function exists.

Step-size cap rationale

Caps to [1e-4, 0.3] (not 0.5): the comment records that an eps=0.5 + frozen-mass sampling gave <5% acceptance on 2/4 chains in a 72-min laptop test; 0.3 cap keeps all chains productive.

Complexity

O(total_steps × leapfrog × cost(ll)) dominated by the filter. The dense path adds a 3×3 eigh/inv per window — negligible. Memory O(draws × 3) for stored samples plus per-window sample blocks.

Edge cases / bugs

  • Tiny num_burnin: the max(...) floors keep windows ≥4–8 steps, but adaptation quality degrades.
  • Non-PSD window covariance → the 1e-4·I ridge + eigen-clip keep cholesky/inv stable.
  • The synthesized constant step_arr means downstream "final step size" reflects the frozen value, not per-step values (intentional).
  • skip = max(int(wsize*0.25), 1) can leave very few samples for the precision estimate in small windows → noisier mass matrix.

run_chain(...)

Dispatcher: vanilla HMC + dual-averaging, or the windowed engine

If use_windowed_adaptive, it forwards to run_chain_windowed_proper (default target_accept_prob=0.65). Otherwise it builds the vanilla path:

kernel = tfm.HamiltonianMonteCarlo(target_log_prob_fn, step_size, num_leapfrog_steps)
kernel = tfm.DualAveragingStepSizeAdaptation(kernel, num_adaptation_steps=num_burnin,
                                             target_accept_prob=0.65)

Identity mass (no preconditioning) in this path — appropriate when the posterior geometry is roughly spherical. target_accept=0.65 is Hoffman & Gelman's recommendation for fixed-L HMC.

Robust trace_fn: it drills through arbitrarily many inner_results layers with a while hasattr(...) loop, then defensively reads is_accepted / target_log_prob with hasattr fallbacks — so it survives different wrapper depths.

Two sub-paths by progress_every:

  • progress_every <= 0: a single fused tfm.sample_chain call with num_burnin_steps=num_burnin (fast, graph-compiled, silent).
  • progress_every > 0: an explicit Python loop calling kernel.one_step with bootstrap_results, collecting per-step state and printing heartbeat lines. Slower but observable; only post-burn states are kept.

Returns (samples, acc, lp, step) as NumPy arrays in both paths. Complexity O(total × leapfrog × cost(ll)). Edge cases: the looped path seeds one_step with [seed, s+1] (a 2-vector "stateless" seed) — a different RNG convention than the fused path's scalar seed.

split_rhat(samples) & ess_bulk(samples)

Convergence (R-hat) and efficiency (ESS) diagnostics

split_rhat — Gelman–Rubin on split half-chains. With <2 chains it returns NaN (R-hat undefined). It splits each chain in half and treats the halves as extra chains (so even 2 chains give 4 sequences), then computes the classic between/within variance ratio:

B = N · var_across_sequences(means)        # between
W = mean(within-sequence variances)        # within
var_hat = ((N-1)/N)·W + B/N
Rhat = sqrt(var_hat / W)

R-hat ≈ 1.00 ⇒ chains agree (converged); >1.01–1.1 ⇒ trouble. Splitting catches within-chain non-stationarity (drift) that plain R-hat misses.

ess_bulk — loops parameter-by-parameter so TFP's effective_sample_size sees a clean (chains, draws) tensor and broadcasts cross_chain_dims=[0]; with 1 chain it computes per-chain ESS. ESS estimates the number of independent draws after accounting for autocorrelation — the real currency of MCMC efficiency.

Complexity: R-hat O(chains·draws·dim); ESS O(dim · chains · draws log draws) (FFT autocorrelation). Edge cases: both guard the 1-chain case; R-hat clamps the denominator with max(W, 1e-12) to avoid divide-by-zero.

summarise_posterior(samples_constrained, truth) → list[dict]

Per-parameter summary rows incl. coverage & bias

Builds one dict per parameter (mu, phi, sigma_eta_sq) plus a derived sigma_eta row computed as sqrt(sigma_eta_sq). For each it records mean, std (ddof=1), median, 2.5/97.5% quantiles, R-hat, ESS, a boolean 95% CI coverage of truth, and both percent and absolute bias.

truth_arr = [mu, phi, sigma_eta**2]     # note: variance, to match sigma_eta_sq
flat = samples_constrained.reshape(-1, 3)   # pool all chains for marginals
covered = q025 <= truth_val <= q975

Important design choices: R-hat/ESS use the structured (chains, draws, dim) array (cross-chain), but means/quantiles use the pooled flat array. The derived sigma_eta row sets R-hat/ESS to NaN (those are reported on the sampled coordinate sigma_eta_sq, not the transform). bias_pct guards near-zero truth (|truth|>1e-3) returning NaN for mu=0 — which is exactly the default truth, so mu's bias% is typically NaN by design.

Complexity O(chains·draws·dim). Edge cases: np.maximum(flat[:,2],1e-12) before sqrt guards negative round-off; ddof=1 needs ≥2 samples.

_write_reports_and_plots(...) → int

Console table, defensive .npz, txt/json reports, matplotlib figures
  • Defensive .npz first: saves stacked samples_raw/constrained/accept/log_prob/step_size/truth before printing, so a crash mid-report still leaves data. The step_size field handles both list-of-arrays and array inputs.
  • Console + txt: a fixed-width table (truth/mean/std/median/CI/R-hat/ESS/bias/ coverage) plus per-chain and overall accept rates and final step sizes. The txt report also appends the documented HRS sigma_eta-bias caveat and the KSC(1998) fix pointer.
  • JSON: same content machine-readable, including vars(args) config echo.
  • Plots (if _HAVE_MPL): per-chain traceplots (one panel per param, truth as red dashed line) and pooled posterior marginals (histograms with truth + posterior-mean lines). Saved at 120 dpi, figures explicitly plt.close()d to free memory.

Returns 0. Complexity O(chains·draws). Edge cases: bias_pct NaN renders as nan% in the table; the step_size stacking branch is the trickiest line (mixed types).

_aggregate_from_chains(_args, out_dir) → tuple

Globs out_dir/chains/chain_*.npz (sorted), loads each, and np.stacks them into the same (chains, …) arrays the sequential path produces — so downstream diagnostics are identical. Wall time is reported as max of per-chain elapsed (because the chains were meant to run in parallel processes). Raises FileNotFoundError if no chain files exist. _args is reserved for future use. This is what enables the parallel-launcher workflow: spawn N processes each with --chain_id k, then one process with --aggregate.

main() → int

Argument surface and three-mode dispatch

Args cover: truth (mu/phi/sigma_eta), data size (T), filter knobs (N, n_lambda, K, L), HMC knobs (step_size, num_chains, num_burnin, num_results, dispersion), seeds, progress_every, out_dir, the six prior hyperparameters, and the mode/kernel toggles (chain_id, aggregate, use_windowed_adaptive, diagonal_mass, no_likelihood).

Note on defaults: prior_phi_raw_loc=2.0, scale=0.5 concentrates phi near tanh(2)≈0.964 — a weakly-informative prior tuned to keep the chain out of the near-non-stationary mode at small T (the docstring of make_target_log_prob explains this).

Dispatch order: (1) --aggregate short-circuits to load+diagnose+report; otherwise it generates data, builds ll and the target, then (2) if --chain_id is set runs exactly that chain and saves it, else (3) loops all chains sequentially and writes the combined report.

Inits: truth_raw = unconstrain(mu, phi, sigma_eta**2) then per chain add dispersion · standard_normal(3) — dispersed starts are what make R-hat meaningful (chains must start apart to prove they mix to the same place). crn_seed = base_seed is shared across chains so the target is the same function for all of them.

Complexity dominated by sampling. Edge cases: chain_id out of range raises ValueError; the chains/ dir is always created even in sequential mode.

7 · Algorithm Walkthrough

HMC / Preconditioned HMC

Intuition. Treat −log posterior as a potential energy surface; add a random momentum, simulate frictionless physics (leapfrog integration) for L steps, then accept/reject with a Metropolis correction for integration error. Momentum lets the sampler take long, low-rejection moves instead of a random walk.

Mapping to code. num_leapfrog_steps = L is the trajectory length; step_size = eps is the leapfrog step. The target's gradient (autodiff through ll) is the force. The momentum_distribution is the mass matrix — preconditioning. Runtime per step ≈ L gradient evals; each gradient eval is one filter pass.

Dual-averaging step-size adaptation

Intuition. Tune eps during warmup so the average acceptance hits a target (0.65). Nesterov dual-averaging adjusts log eps and keeps a smoothed running average (log_averaging_step) used as the final value. Too-large eps → high rejection; too-small → tiny moves.

Windowed mass-matrix adaptation (Stan-style)

Intuition. The ideal mass matrix is the posterior precision (inverse covariance): it "sphericises" the geometry so leapfrog steps are equally good in every direction. You don't know it a priori, so estimate it in expanding windows, each time re-centring the step-size adaptation. Code mapping: per window → covariance(win) → clip eigenvalues → inv → precision → MultivariateNormalTriL(scale_tril=cholesky(precision)). Runtime adds tiny 3×3 linear algebra; memory negligible vs the filter.

Unconstrained reparameterisation

tanh for phi∈(-1,1), exp for sigma_eta_sq>0. Lets HMC run on ℝ³. Runtime O(1).

SVSSM data generation

AR(1) latent recursion + multiplicative observation noise; O(T). (See §5 gen_svssm.)

split-R-hat & ESS

Variance-ratio convergence and autocorrelation-based effective sample size — the two numbers that decide whether the run can be trusted. (See §5.)

8 · Data Flow

Narrative. Truth → gen_svssm → y_obs (fixed). The sampler proposes theta_raw; the target maps it to phi/σ², adds the prior, calls ll(...,y_obs) for the data term, returns a scalar log-post that drives accept/reject. Accepted theta_raw draws accumulate to (chains, draws, 3), are constrained to natural space, summarised, and written to disk.

9 · Memory Analysis

  • Dominant footprint: the sample arrays (chains, draws, 3) in float32 — tiny (e.g. 4×400×3×4B ≈ 19 KB). The real memory cost lives inside ll (particles × T), which this file doesn't own.
  • Per-step allocations: each leapfrog gradient builds a fresh autodiff graph through ll — transient, freed after the step.
  • Window sample blocks: samples_w per warmup window are temporary; only their covariance is retained (as the new momentum dist).
  • Copies vs references: .numpy() calls copy device tensors to host; intentional, at chain boundaries only. final_state = samples[-1] is a view/slice, cheap.
  • Plot figures: explicitly plt.close()d to release Agg buffers — important in long batch runs.
  • GC considerations: closures capture ll, y_obs, priors for the whole run; they persist until main returns. No leaks of note.

12 · Modification Guide

  • Swap the likelihood: only make_target_log_prob calls ll(mu, phi, sigma_eta_sq, y_obs) and main constructs it. Any object with that call signature drops in (e.g. a KSC mixture). Tightly coupled to the 4-arg interface.
  • Add a parameter: touches unconstrain/constrain (add a coordinate + its transform), theta_raw indexing in the closure, the state_dim=3 assumptions, summarise_posterior's name/truth arrays, and the plotting loops. These are the tightly-coupled "magic 3" sites.
  • Change priors: just pass different CLI hyperparameters — no code change.
  • Switch sampler: --use_windowed_adaptive / --diagonal_mass already toggle this. To add NUTS, add a branch in run_chain mirroring the vanilla path with tfm.NoUTurnSampler.
  • Parallelise: already supported via --chain_id + --aggregate; wire a shell/launcher to fan out processes.
  • Refactor risk: the getter/setter and trace lambdas are coupled to TFP's namedtuple layout — change with care and test kernel.bootstrap_results structure first.

16 · Refactoring Suggestions

  • Magic number 3: state_dim=3, the [mu,phi,σ²] name list, and indexing are scattered. Introduce a small PARAM_NAMES / N_PARAMS constant and a Bijector object to centralise the transform (TFP's tfb.Chain([Identity, Tanh, Exp]) would also give free Jacobians).
  • Duplicated chain-run block: the single-chain and sequential paths in main repeat the run_chain call + logging. Extract a _run_one_chain(c) helper.
  • Duplicated table formatting: the console and txt reports build nearly identical fixed-width rows — factor a format_row(r).
  • Closure global-seed side effect: resetting the global TF seed inside the target is a code smell; prefer a stateless seed threaded into the filter if its API allows.
  • TFP-coupled lambdas: wrap the getter/setter/trace plumbing in one small adapter class with a version-guard, so a TFP bump touches one place.
  • Naming: unconstrain takes the variance but is named for the general transform — a docstring-level sigma_eta_sq note helps; consider unconstrain_var.
  • gen_svssm: replace the eager Python loop with tf.scan for speed and to drop the global-seed reliance.
